This sequence uses the default constructor and assumes successful storage operations. K₁/K₂ and E₁/E₂ are labels, not API counters. The application owns all access to this storage; it must quiesce any other owners before resetting. Playback is conceptual, not a recorded execution or timer.

Read the distinction without playback

Reopening retains the stored key, entity state and event history. The newly constructed Node loads that key and uses a fresh local epoch. Its Contexts and queries are new objects.

Reset first halts the original Node, closes admission and drains its work. It then empties storage. The original Node remains halted even after success. Constructing a successor creates a new epoch and, with no stored key left, a new key. If the application supplies its own key, reset cannot erase that external copy: reusing it preserves the NodeId.
